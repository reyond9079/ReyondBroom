## Reproduction

Build the native module using the repository's Linux build dependencies and
updated source. The checks also run independently of the engine:

```sh
scripts/test-audio-core.sh /tmp/reyond-audio-qa /usr/bin/ffmpeg
DISPLAY=:99 scripts/test-audio-editor-linux.sh /path/to/ReyondBroom-Linux-x64 /tmp/reyond-native-qa
DISPLAY=:99 python3 scripts/capture-audio-editor-linux.py /path/to/ReyondBroom-Linux-x64 /tmp/reyond-native-qa
```

For the last command, use an X server at least 2560×1600. Native fixtures are
synthetic, deterministic waveforms generated by `audio-editor-fixtures.py`.
Screenshot panels and exported audio come from the C++ editor; these are not the
HTML mockup or manually painted application images.

The Linux native suite runs with `-nosound` to isolate UI/file/resource checks.
A separate run uses the real FTE RawAudio output through PulseAudio into a null
sink. FFmpeg records the sink monitor; FFT of the strongest 0.5-second window
finds **440 Hz left / 660 Hz right**, RMS approximately **0.1074**, peak **0.1711**.
This verifies that audio traverses the engine output path. It does not verify
physical loudspeakers, device latency or subjective audio quality. The attached
loopback sample contains the captured output, with surrounding silence trimmed.

The model suite also passes AddressSanitizer and UndefinedBehaviorSanitizer.
Converter paths containing spaces, quotes and Cyrillic are exercised. Process
cancellation is tested both before export and after a child has launched.

## Limits of the checks

- Physical microphone selection, hot unplug, acoustic feedback, output hardware,
  device-specific latency, localized keyboard layouts and Windows interactive UI
  are not claimed tested in this headless Linux environment.
- The FTE output API has no consumed-frame query. The playhead estimates consumed
  frames from the monotonic queue clock; it is not sample-accurate device timing.
- The master graph clamps sample peaks at 0 dBFS. Clip loudnorm uses −1 dBTP;
  summing/resampling/lossy encoding can produce a different final true peak.
- Processed clips are reanalysed after split/trim. Echo tails end at clip bounds.
  Resource updates reencode and do not preserve loop/cue/custom metadata.
- CapCut's exact build and full proprietary preset remain unknown; the accepted
  public-reference mockup and proposed preset are the comparison baseline.

Windows CI compiles the actual native module and runs the same graph/DSP tests
against the rebuilt, file-only bundled converter. See `audio-editor-checks.yml`
for pinned corresponding sources and uploaded QA artifacts. The final run for runtime commit `cec617f30f021f415e847bc64a7798eef59d2853`
[passed](https://github.com/reyond9079/ReyondBroom/actions/runs/42239350372).
It builds the real Windows module and tests the rebuilt converter, including
four codecs, 0.25–4× pitch-preserving speed, normalization, cancellation, quoted
Unicode converter paths and multichannel rejection. [Windows results](logs/windows.log).
The subsequent evidence commit changes only QA documentation, screenshots and logs.
