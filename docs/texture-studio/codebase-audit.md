# Texture Studio codebase audit

RB-23 starts from clean source revision `71cc3785ef9445a2c7591fdc43b9e4e59a1117f4`, the revision tagged `v0.6.0-alpha.31`. The [baseline build and selected regression workflow](https://github.com/reyond9079/ReyondBroom/actions/runs/44315951212) ran on Windows x64, Linux x64 and Linux SDL2 x64 from a checkout pinned to that revision. The developer worktree is `codex/rb23-texture-studio`.

## Native integration points

- The main plugin in `native/ftebroom.cpp` runs Dear ImGui in the FTE engine and routes registered console commands through the native plugin and CSQC. `assetsMenu()` in `native/ftebroom_actions.h` is the shared entry point for offline asset tools. `materialBrowser()` in `native/ftebroom_materials.h` owns the face inspector and asset list. `uiScale()` supplies UI scale and `native/ftebroom_modern_theme.h` provides Modern Dark and Light styling. `native/ftebroom_workspace.h` constructs the workspace dock. `runUiRecordGlobal()` provides the read-only coordinates consumed by native input tests.
- `organizationMapEpoch` and `ftebroom_map_instance` identify native and CSQC map sessions. QuakeC stores selected brush identities and selected face masks in `selectedbrushes`. `fb_tx_begin()`, `fb_tx_commit()` and `fb_tx_cancel()` in `qc/fb_transaction.qc` form real history transactions. The material actions in `qc/fb_materials.qc` and `qc/ftebroom.qc` copy and change face shader names while retaining face vectors and biases. `native/ftebroom_document.h` and `qc/ftebroom_document.qc` manage existing MAP persistence. The editor must validate captured face identities and map revision before the material transaction.
- `native/ftebroom_bb_ui_viewport.h` renders model previews. `native/ftebroom_bb_ui_panels.h` and `native/ftebroom_bb_ui_actions.h` own model textures and selection. The shared Bitmap/Model Editor document and undo stack must own model-slot changes. The assets panel must pass an explicit slot identity and revision to that owner.
- `native/ftebroom_plant_editor.h` and `native/ftebroom_entity_preview.h` already use immutable inputs with background `std::async` and poll futures through the UI. Engine image handles belong to the render thread. Texture Studio can publish CPU preview pixels through the same native image upload path as the plant preview.
- `gameProfileName()` and `gameRuntime()` in `native/ftebroom_game_profile.h` resolve the active FTE Custom, Quake III Arena, Quake 1, Quake II or Half-Life environment. `modFileRoot()` resolves the writable mod root. `native/ftebroom_build.h` drives separate compiler stages. `q1Palette()` and `q2Palette()` resolve profile-local palettes. `native/ftebroom_legacy_images.h`, `native/ftebroom_quake1.h` and `native/ftebroom_wad_import.h` supply existing validation and decode paths. Reuse readers for editor integration and verify emitted containers independently. The current WAD writer averages palette colors in byte space, so texture-source mip generation needs a linear-light path.
- `placementPublish()` in `native/ftebroom_placement.h` installs generated immutable bundles, checks for content conflicts, merges shader lists and requests `fs_flush`. `bb::atomicWrite()` in `native/ftebroom_bb_io.h` is the sibling-temp replace primitive. It does not replace a multi-file transaction journal. Existing projects and map formats stay intact.
- The portable engine modules build as C++17 headers under the native plugin. Editor behavior also compiles from `qc/csaddon.src` using FTEQCC. Existing CI entry points are `scripts/ci-plan.py`, `scripts/ci-run-checks.py` and `scripts/ci-release-smoke.py`. The latter verifies corresponding source, checksums, manifests and startup across the three runtime packages. A separate headless Texture Studio target can use the same C++17 module with no engine ABI.
- Active publication is through `.github/workflows/release-linux-ui-update.yml`. Other checked-in publish workflows pin or stage particular historical releases. `scripts/check-character-release.py` provides a precedent for exact revisions and hashed evidence. A Texture Studio package must be checked independently of the RB-21 gate. Server-side environment and tag enforcement remains a separate condition to verify.
- New source uses the combined editor distribution license, GPL-3.0-or-later, as documented in `THIRD-PARTY.md`. The existing JSON implementation is `native/third_party/json.hpp`. Existing PNG/TGA/JPEG and compression facilities should be reused where their bounds and determinism meet the export contract. No commercial textures or game palettes are needed for built-in generation.

## Evidence still required

Five engine runtimes and the pinned FTE material conventions require profile-specific evidence. Existing editor and compilation tests do not prove an arbitrary texture encoding or rich FTE material path. This audit does not claim Texture Studio tests, performance, or publication checks have run.
